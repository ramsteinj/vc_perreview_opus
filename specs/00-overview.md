# 00. 프로젝트 개요

## 1. 목적

조직 구성원의 성과를 평가하고, **개인 평가 점수**와 **부서 성과 점수**를 합산하여
최종 성과 점수(0~100)를 산출하는 웹 기반 인사평가 시스템(Performance Review App)이다.

## 2. 사용자 유형

| 역할 | 코드 | 설명 |
|------|------|------|
| 직원 | `EMPLOYEE` | 로그인하여 본인에게 배정된 평가 문항에 응답한다. |
| 관리자 | `ADMIN` | 사용자/부서/평가 항목/평가자 배정을 관리하고, 응답 현황을 모니터링하며, 점수를 산출·다운로드한다. |

> 한 사용자는 동시에 "평가 대상자(피평가자)"이면서 "평가자"일 수 있다.
> 평가자 여부는 별도 플래그가 아니라 **평가자 배정(EvaluatorAssignment) 데이터의 존재**로 결정된다.

## 3. 핵심 도메인 흐름

```
[관리자] 부서 등록 → 사용자 등록 → 평가 회차 생성
            ↓
        평가 항목 정의 (개인용 / 부서용) + 항목별 가중치 부여
            ↓
        1차 / 2차 평가자 배정 (2차는 선택)
            ↓
        평가 회차 OPEN
            ↓
[직원=평가자] 로그인 → 배정된 평가 대상 목록 확인
            ↓
        평가 문항 응답 (임시 저장 / 진행률 표시)
            ↓
        제출 (SUBMITTED) → 중복 응답 차단
            ↓
[관리자] 응답 현황 모니터링 (요약 / 상세 / 미응답자)
            ↓
        평가 회차 CLOSED → 점수 산출
            ↓
        개인 점수 + 부서 성과 가감 → 최종 점수 (0~100)
            ↓
        CSV 다운로드
```

## 4. 용어집 (Glossary)

| 용어 | 영문/모델명 | 정의 |
|------|------------|------|
| 사번 | `employee_no` | 사내 고유 직원 번호. 로그인 식별자로 사용된다. |
| 성명 | `name` | 직원 이름. 로그인 시 사번과 함께 검증한다. |
| 평가 회차 | `EvaluationCycle` | 평가가 진행되는 기간 단위 (예: 2026년 상반기 평가). |
| 평가 항목 | `EvaluationItem` | 평가 문항. 대상 유형(개인/부서)과 가중치를 가진다. |
| 가중치 | `weight` | 항목별 비중(%). 동일 회차·동일 대상 유형 내 합계가 100이어야 한다. |
| 1차 평가자 | `PRIMARY` | 필수 평가자. 보통 직속 상급자. |
| 2차 평가자 | `SECONDARY` | 선택 평가자. 보통 차상급자. |
| 평가지 | `EvaluationResponse` | 평가자 1명이 대상 1개에 대해 작성하는 응답지 한 장. |
| 답변 | `EvaluationAnswer` | 평가지 내 개별 항목에 대한 점수/코멘트. |
| 개인 평가 점수 | `individual_score` | 개인 평가 항목 기반 가중 합산 점수 (0~100). |
| 부서 성과 점수 | `department_score` | 부서 평가 항목 기반 가중 합산 점수 (0~100). |
| 부서 가감 | `department_adjustment` | 부서 성과 점수를 개인 점수에 반영하는 가감값(±). |
| 최종 점수 | `final_score` | `clamp(개인 점수 + 부서 가감, 0, 100)`. |

## 6. 범위 밖 (Out of Scope)

현 단계에서 구현하지 않는다. 필요 시 별도 요구사항으로 추가한다.

- 이메일/SMS 알림 발송
- SSO / LDAP / OAuth 연동
- 다국어(i18n) 지원 — UI는 한국어 단일
- 모바일 네이티브 앱
- 평가 결과에 대한 피평가자 이의제기 워크플로
- 목표관리(MBO/OKR) 설정 및 추적
