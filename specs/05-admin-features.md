# 05. 관리자 기능 상세 요구사항

모든 관리자 API는 `IsAdminRole` 권한(`request.user.role == 'ADMIN'`)을 요구한다.

---

## FR-A-01. 기본 관리자 계정 자동 생성

앱 시작 시 관리자 계정이 없으면 `성명: ADMIN / 사번: ADMIN / 비밀번호: admin1234!`로
생성한다. 구현 상세는 [03-auth.md](03-auth.md) §5 참조.

### 수용 기준

- [ ] 빈 DB에 `migrate`를 실행하면 기본 관리자 계정이 생성된다
- [ ] 생성된 계정으로 `ADMIN / ADMIN / admin1234!` 로그인이 성공한다
- [ ] `migrate`를 다시 실행해도 계정이 중복 생성되지 않는다
- [ ] 다른 관리자 계정이 이미 있으면 기본 계정을 생성하지 않는다
- [ ] 기본 비밀번호가 변경되지 않은 상태면 로그인 후 변경 안내 배너가 표시된다

## FR-A-02. 사용자 관리 (추가 / 수정 / 삭제)

### 목록 화면

| 컬럼 | 비고 |
|------|------|
| 사번 | 정렬 가능 |
| 성명 | 검색 대상 |
| 부서 | 필터 |
| 직위 | |
| 권한 | `EMPLOYEE` / `ADMIN` 필터 |
| 상태 | 재직 / 비활성 필터 |
| 액션 | [수정] [비밀번호 초기화] [비활성화] |

- 검색: 사번·성명 부분 일치
- 필터: 부서, 권한, 재직 상태
- 페이지네이션: 페이지당 25건

### 추가

```
POST /api/admin/users/
{
  "employee_no": "20260101",
  "name": "홍길동",
  "department": 3,
  "position": "선임",
  "role": "EMPLOYEE",
  "hired_on": "2026-01-01",
  "password": "initialPass1!"
}
```

- `employee_no` 중복 시 `400`과 함께 필드 오류 반환
- `password` 미지정 시 서버가 임시 비밀번호를 생성해 **응답에 1회만** 포함한다
- 비밀번호는 Django validator를 통과해야 한다

### 수정

```
PATCH /api/admin/users/{id}/
```

- `employee_no` 변경은 허용하되, 평가 이력이 있으면 경고를 표시한다
- 비밀번호는 이 엔드포인트로 변경하지 않는다.
  별도 엔드포인트: `POST /api/admin/users/{id}/reset-password/`
- 본인(`request.user`)의 `role`을 `EMPLOYEE`로 낮추는 것은 차단한다
  (마지막 관리자가 스스로 권한을 잃는 사고 방지)

### 삭제

**소프트 삭제를 기본으로 한다.**

```
DELETE /api/admin/users/{id}/     →  is_active = False
```

- 평가 이력(`EvaluationResponse`, `EvaluatorAssignment`, `ScoreResult`)이 있는
  사용자는 물리 삭제할 수 없다 (FK `PROTECT`)
- 이력이 전혀 없는 사용자에 한해 `?hard=true`로 물리 삭제를 허용한다
- **활성 관리자가 1명뿐이면 비활성화를 거부한다** (`409 LAST_ADMIN`)
- 진행 중(`OPEN`) 회차의 평가자로 배정된 사용자를 비활성화하려 하면 경고와 함께
  영향받는 배정 목록을 반환한다. `?force=true`로 진행 가능

### 일괄 등록 (선택 구현)

CSV 업로드로 사용자를 일괄 등록한다.
컬럼: `employee_no, name, department_code, position, role, hired_on`
검증 실패 행은 사유와 함께 리포트하고, 전체를 롤백한다.

### 수용 기준

- [ ] 중복 사번으로 등록하면 400이 반환된다
- [ ] 평가 이력이 있는 사용자를 삭제하면 비활성화만 되고 데이터는 보존된다
- [ ] 마지막 관리자 계정은 비활성화할 수 없다
- [ ] 비활성 사용자는 로그인할 수 없다

## FR-A-03. 부서 관리

### 기능

| 기능 | 엔드포인트 |
|------|-----------|
| 목록 (트리) | `GET /api/admin/departments/?tree=true` |
| 생성 | `POST /api/admin/departments/` |
| 수정 | `PATCH /api/admin/departments/{id}/` |
| 삭제 | `DELETE /api/admin/departments/{id}/` |

```json
{ "code": "DEV1", "name": "개발1팀", "parent": 2, "is_active": true }
```

### 규칙

- `code`는 전체에서 유일하다
- `parent` 순환 참조를 금지한다 (자기 자신 또는 자손을 부모로 지정 불가)
- 하위 부서나 소속 직원이 있는 부서는 물리 삭제할 수 없다 → 비활성화로 처리
- 비활성 부서는 신규 사용자 배정·평가자 지정 대상에서 제외된다

### 수용 기준

- [ ] 부서 트리가 계층 구조로 표시된다
- [ ] 순환 참조를 만들려 하면 400이 반환된다
- [ ] 소속 직원이 있는 부서 삭제 요청은 비활성화로 처리된다

## FR-A-04. 평가 항목 관리 + 가중치 부여

부서 평가 항목과 직원(개인) 평가 항목을 각각 관리한다.

### 화면

회차를 선택한 뒤, `개인 평가 항목` / `부서 평가 항목` 탭으로 나누어 편집한다.

```
┌──────────────────────────────────────────────────────┐
│ 2026년 상반기 평가   [개인 항목] [부서 항목]           │
├──────────────────────────────────────────────────────┤
│ 순서  코드      제목            가중치   척도   활성   │
│  ↕ 1  PERF     업무 성과        [50] %   [5]   [v]   │
│  ↕ 2  COLLAB   협업             [30] %   [5]   [v]   │
│  ↕ 3  ATTITUDE 태도             [20] %   [5]   [v]   │
├──────────────────────────────────────────────────────┤
│ 가중치 합계: 100%  ✅                   [+ 항목 추가]  │
└──────────────────────────────────────────────────────┘
```

### 규칙

- 항목은 **회차에 종속**된다. 회차를 새로 만들면 항목도 새로 정의한다
  (이전 회차에서 복제하는 기능 제공: `POST /api/admin/cycles/{id}/clone-items/`)
- `order`는 드래그 앤 드롭으로 변경할 수 있다
- **가중치 합계 검증**
  - 편집 중에는 합계가 100이 아니어도 저장할 수 있다
  - 화면에 실시간 합계를 표시하고, 100이 아니면 경고 배지(`⚠ 합계 95%`)를 띄운다
  - **회차를 `OPEN`으로 전이할 때 합계가 정확히 100.00이 아니면 거부한다**
    (`400 WEIGHT_SUM_INVALID`, 대상 유형과 현재 합계를 응답에 포함)
- `weight > 0`이어야 한다. 0이나 음수는 거부
- **응답이 하나라도 존재하는 항목은 `weight`, `max_score` 변경과 삭제를 차단한다**
  (`409 ITEM_IN_USE`). 이미 매겨진 점수의 의미가 바뀌기 때문이다

### 수용 기준

- [ ] 가중치 합계가 100이 아닌 회차는 OPEN으로 전환되지 않는다
- [ ] 개인 항목과 부서 항목의 가중치 합계를 각각 독립적으로 검증한다
- [ ] 응답이 있는 항목의 가중치를 변경하면 409가 반환된다
- [ ] 항목 순서를 변경하면 직원의 응답 화면에도 반영된다

## FR-A-05. 1차 / 2차 평가자 지정

부서와 직원 각각에 대해 1차 평가자(필수)와 2차 평가자(선택)를 지정한다.

### 화면

```
┌──────────────────────────────────────────────────────────────┐
│ 평가자 배정 · 2026년 상반기 평가   [개인 대상] [부서 대상]      │
├──────────────────────────────────────────────────────────────┤
│ 대상          부서       1차 평가자*      2차 평가자(선택)      │
│ 김철수        개발1팀    [박팀장     v]   [최본부장   v]       │
│ 이영희        개발1팀    [박팀장     v]   [          v]       │
│ 정민수        디자인팀   [ 미지정    v]⚠  [          v]       │
├──────────────────────────────────────────────────────────────┤
│ 미배정 2명                          [일괄 배정] [저장]         │
└──────────────────────────────────────────────────────────────┘
```

### 규칙

- **1차 평가자는 필수, 2차 평가자는 선택**이다
- 1차와 2차 평가자는 서로 달라야 한다 (`400 EVALUATOR_DUPLICATE`)
- 개인 대상일 때 평가자는 피평가자 본인이 될 수 없다 (`400 SELF_EVALUATION`)
- 하나의 (회차, 대상)에 배정은 하나만 존재한다 (Unique 제약)
- 미배정 대상을 목록 상단에 요약 표시한다
- **회차를 `OPEN`으로 전이할 때 1차 평가자가 미지정인 대상이 있으면 경고**한다.
  차단하지는 않되(부분 운영 허용), 미배정 목록을 반환해 확인을 요구한다

### 일괄 배정 (편의 기능)

- 부서 단위로 "해당 부서 전원의 1차 평가자를 X로 설정" 일괄 적용
- 부서의 `parent` 부서장을 2차 평가자로 자동 제안

### 2차 평가자 미지정 시 점수 처리

`individual_score = primary_score` (1차 100% 반영).
자세한 내용은 [06-scoring.md](06-scoring.md) §3 참조.

### 수용 기준

- [ ] 1차 평가자 없이 저장하면 400이 반환된다
- [ ] 2차 평가자 없이 저장하면 정상 저장된다
- [ ] 본인을 본인의 평가자로 지정하면 400이 반환된다
- [ ] 1차와 2차에 같은 사람을 지정하면 400이 반환된다
- [ ] 평가자로 지정되면 해당 사용자의 "내 평가 목록"에 대상이 나타난다

## FR-A-06. 응답 현황 조회 (요약 / 상세 / 미응답자)

### 6-1. 요약 (Summary)

```
GET /api/admin/cycles/{id}/status/summary/
```

```json
{
  "cycle": { "id": 3, "name": "2026년 상반기 평가", "status": "OPEN",
             "ends_on": "2026-09-30", "days_left": 14 },
  "overall": {
    "total_responses": 256, "submitted": 198, "draft": 31,
    "not_started": 27, "submission_rate": 77.34
  },
  "by_round": {
    "PRIMARY":   { "total": 128, "submitted": 112, "rate": 87.50 },
    "SECONDARY": { "total": 128, "submitted": 86,  "rate": 67.19 }
  },
  "by_target_type": {
    "EMPLOYEE":   { "total": 240, "submitted": 186, "rate": 77.50 },
    "DEPARTMENT": { "total": 16,  "submitted": 12,  "rate": 75.00 }
  },
  "by_department": [
    { "department_id": 3, "department_name": "개발1팀",
      "total": 24, "submitted": 22, "draft": 1, "not_started": 1, "rate": 91.67 }
  ]
}
```

**상태 정의**

| 상태 | 판정 |
|------|------|
| 제출완료 | `EvaluationResponse.status == SUBMITTED` |
| 임시저장 | `status == DRAFT` (레코드 존재) |
| 미시작 | 배정은 있으나 `EvaluationResponse` 레코드가 없음 |

> **분모는 `EvaluationResponse`가 아니라 "배정으로부터 도출되는 기대 응답 수"다.**
> 1차 배정 1건 + 2차 평가자 지정 1건 = 기대 응답 2건.
> 아직 작성을 시작하지 않아 레코드가 없는 건도 분모에 포함해야 한다.

### 6-2. 상세 (Detail)

```
GET /api/admin/cycles/{id}/status/detail/?department=3&status=NOT_STARTED&round=PRIMARY
```

| 컬럼 | 설명 |
|------|------|
| 평가자 | 성명 (사번) |
| 평가자 부서 | |
| 평가 대상 | 성명 또는 부서명 |
| 대상 유형 | 개인 / 부서 |
| 차수 | 1차 / 2차 |
| 상태 | 미시작 / 임시저장 / 제출완료 |
| 진행률 | % |
| 제출 시각 | |
| 액션 | [응답 보기] [반려] |

- 필터: 부서, 상태, 차수, 대상 유형, 평가자명/사번 검색
- 정렬: 상태, 진행률, 제출 시각
- 페이지네이션 필수 (기대 응답 수가 수천 건까지 커질 수 있음)

### 6-3. 미응답자 모니터링

```
GET /api/admin/cycles/{id}/status/pending/
```

**미응답자 = 제출하지 않은 평가자** (미시작 + 임시저장)

평가자 단위로 그룹핑해서 반환한다. 독려 대상을 한눈에 보기 위함이다.

```json
{
  "count": 23,
  "results": [
    {
      "evaluator": { "id": 12, "employee_no": "20180055",
                     "name": "박팀장", "department_name": "개발1팀" },
      "pending_count": 4,
      "not_started": 2,
      "draft": 2,
      "pending_targets": [
        { "target_name": "김철수", "target_type": "EMPLOYEE",
          "round": "PRIMARY", "status": "DRAFT", "progress": 33 }
      ]
    }
  ]
}
```

- 정렬: 미응답 건수 내림차순
- 미응답자 목록도 CSV로 내려받을 수 있다
- 알림 발송은 범위 밖 ([00-overview.md](00-overview.md) §6)

### 6-4. 평가지 반려 (Reopen)

```
POST /api/admin/responses/{id}/reopen/
{ "reason": "평가 기준 재안내에 따른 재작성 요청" }
```

- `SUBMITTED` → `DRAFT`로 되돌리고 `submitted_at = null`
- 이미 산출된 `ScoreResult`가 있으면 재산출이 필요함을 응답에 표시한다
- 반려 사유를 로그로 남긴다

### 수용 기준

- [ ] 미시작(레코드 없음) 건이 분모와 미응답자 목록에 포함된다
- [ ] 부서별 제출률이 정확히 계산된다
- [ ] 상세 목록에서 부서·상태 필터가 조합해서 동작한다
- [ ] 반려한 평가지는 평가자의 목록에서 다시 수정 가능 상태가 된다

## FR-A-07. 구성원 평가 CSV 다운로드

```
GET /api/admin/cycles/{id}/export/scores.csv
GET /api/admin/cycles/{id}/export/responses.csv
GET /api/admin/cycles/{id}/export/pending.csv
```

### 7-1. 점수 결과 CSV (`scores.csv`)

| 컬럼 | 예시 |
|------|------|
| 회차 | 2026년 상반기 평가 |
| 사번 | 20210133 |
| 성명 | 김철수 |
| 부서코드 | DEV1 |
| 부서명 | 개발1팀 |
| 직위 | 선임 |
| 1차 평가자 | 박팀장 |
| 1차 점수 | 82.00 |
| 2차 평가자 | 최본부장 |
| 2차 점수 | 90.00 |
| 개인 평가 점수 | 84.40 |
| 부서 성과 점수 | 90.00 |
| 부서 가감 | 4.00 |
| **최종 점수** | **88.40** |
| 산출 시각 | 2026-09-16 10:22 |

### 7-2. 응답 상세 CSV (`responses.csv`)

항목별 원점수까지 포함한 전체 응답 내역. 컬럼은 항목 수에 따라 동적으로 확장된다.

```
사번,성명,부서,차수,평가자,상태,제출시각,PERF,PERF_의견,COLLAB,COLLAB_의견,...,종합의견
```

### 공통 규칙

- **인코딩: UTF-8 with BOM (`utf-8-sig`)**
  — BOM이 없으면 Excel에서 한글이 깨진다. 반드시 BOM을 붙인다
- 줄바꿈: `\r\n`
- 구분자: `,` — 값에 쉼표/따옴표/줄바꿈이 있으면 `csv` 모듈이 이스케이프 처리
- 파일명: `Content-Disposition: attachment; filename*=UTF-8''{urlencoded}`
  예: `2026년_상반기_평가_점수_20260916.csv`
- 응답 헤더: `Content-Type: text/csv; charset=utf-8`
- 대용량 대비 `StreamingHttpResponse` + 제너레이터로 생성한다
- 쿼리는 `select_related` / `prefetch_related`로 N+1을 제거한다
- 필터 파라미터(`department`, `status` 등)를 화면의 필터와 동일하게 지원한다

### 구현 위치

`apps/reports/services/csv_export.py`

```python
class Echo:
    def write(self, value): return value

def stream_scores_csv(cycle):
    writer = csv.writer(Echo())
    yield '﻿'                      # BOM
    yield writer.writerow(HEADERS)
    for row in iter_score_rows(cycle):  # 제너레이터
        yield writer.writerow(row)
```

### 수용 기준

- [ ] Excel에서 열었을 때 한글이 정상 표시된다
- [ ] 성명에 쉼표가 포함되어도 컬럼이 밀리지 않는다
- [ ] 1000명 규모에서 응답 시간이 5초를 넘지 않는다
- [ ] 미산출자(1차 미제출)는 점수 컬럼이 비어 있고 비고에 사유가 표시된다

## FR-A-08. 부서 성과 점수 계산

부서 평가 항목에 대한 평가지로부터 부서별 성과 점수(0~100)를 산출한다.
계산식은 [06-scoring.md](06-scoring.md) §4 참조.

### 화면

```
┌────────────────────────────────────────────────────────────┐
│ 부서 성과 점수 · 2026년 상반기 평가          [재계산]        │
├────────────────────────────────────────────────────────────┤
│ 부서       1차 점수  2차 점수  부서 점수  가감      인원     │
│ 개발1팀     88.00    92.00     89.20    +3.84     24명    │
│ 디자인팀    75.00      -       75.00    +1.00     12명    │
│ 영업팀      62.00    58.00     60.80    -1.84     18명    │
│ 인사팀        -        -         -       0.00      6명 ⚠  │
├────────────────────────────────────────────────────────────┤

- 부서 평가지가 미제출인 부서는 `-`로 표시하고 경고 아이콘을 붙인다

### 수용 기준

- [ ] 부서 평가 항목의 가중치에 따라 부서 점수가 계산된다
- [ ] 2차 부서 평가자가 없으면 1차 점수가 100% 반영된다
- [ ] 부서 평가지 미제출 시 소속 직원의 가감값이 0이 된다

## FR-A-09. 최종 합산 점수 산출

```
POST /api/admin/cycles/{id}/calculate/
```

개인 평가 점수에 부서 가감을 적용해 최종 점수(0~100)를 산출하고 `ScoreResult`에 저장한다.
계산식과 산출 결과 응답 형식은 [06-scoring.md](06-scoring.md) §6, §8 참조.

### 결과 조회

```
GET /api/admin/cycles/{id}/scores/?department=3&ordering=-final_score
```

### 화면

```

│ 최종 점수 · 2026년 상반기 평가     [재계산]  [CSV 다운로드]         │
│ 산출 121명 / 전체 128명 · 미산출 7명 ⚠                            │
├──────────────────────────────────────────────────────────────────┤
│ 사번      성명    부서     1차    2차    개인    부서가감   최종    │
│ 20210133 김철수  개발1팀  82.00  90.00  84.40   +3.84    88.24   │
│ 20190022 이영희  개발1팀  91.00    -    91.00   +3.84    94.84   │
│ 20200918 정민수  영업팀   55.00  60.00  56.50   -1.84    54.66   │
│ 20220417 박지훈  인사팀     -      -      -        -       - ⚠   │
└──────────────────────────────────────────────────────────────────┘

- 미산출자는 사유(`PRIMARY_NOT_SUBMITTED` 등)를 툴팁으로 표시한다
- 정렬·필터: 부서, 최종 점수, 개인 점수
- 산출은 회차가 `CLOSED`가 아니어도 실행할 수 있다 (중간 확인 목적).
  단 화면에 "잠정 결과" 표시를 붙인다

### 수용 기준

- [ ] 최종 점수가 0 미만이거나 100을 초과하는 레코드가 존재하지 않는다
- [ ] 재계산을 반복해도 결과가 동일하고 레코드가 중복되지 않는다
- [ ] 1차 미제출자는 산출에서 제외되고 사유가 집계된다
- [ ] 산출 도중 오류가 나면 전체가 롤백된다

## FR-A-10. 평가 회차 관리

| 기능 | 엔드포인트 |
|------|-----------|
| 목록/생성/수정 | `GET|POST /api/admin/cycles/`, `PATCH /api/admin/cycles/{id}/` |
| 상태 전이 | `POST /api/admin/cycles/{id}/open/`, `.../close/` |
| 항목 복제 | `POST /api/admin/cycles/{id}/clone-items/` (source_cycle 지정) |

### OPEN 전이 시 검증

| 검증 | 실패 시 |
|------|---------|
| 개인 항목 가중치 합계 == 100 | 차단 (`400 WEIGHT_SUM_INVALID`) |
| 부서 항목 가중치 합계 == 100 | 차단 (부서 항목이 하나라도 있는 경우에만) |
| 활성 항목이 1개 이상 존재 | 차단 (`400 NO_ACTIVE_ITEMS`) |
| 모든 대상에 1차 평가자 배정 | 경고 (미배정 목록 반환, `?confirm=true`로 진행) |
| `starts_on <= ends_on` | 차단 |

### CLOSE 전이 시

- 미제출 평가지가 있으면 건수를 경고로 반환한다 (`?confirm=true`로 진행)
- 전이 후 자동으로 점수 산출을 실행한다
- `CLOSED` 회차의 항목·배정·응답은 모두 읽기 전용이 된다
